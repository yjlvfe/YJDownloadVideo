> **الهدف:** إضافة أزرار اختيار (فيديو/صوت/دقة) عند إرسال الرابط + قائمة جودات موحدة + إعادة محاولة الرفع (مع الإبقاء على شريط التقدم الحي) + سر توقيع الويب هوك مع فحص/إصلاح + قائمة جودات في واجهة الويب + **حذف فوري للملف بعد نجاح الإرسال** — **دون لمس محرك التحميل إطلاقًا** (قوتنا التي تتفوق على نسختهم في يوتيوب/إنستغرام).

## F1: أزرار الاختيار (القلب)

### التصميم

```
المستخدم يرسل رابط
   ↓
البوت: [🎬 فيديو] [🎵 صوت] [❌ إلغاء]        ← رسالة اختيار (تحمل nonce)
   ↓ المستخدم يختار 🎬 فيديو
البوت: [⭐ الأفضل] [1080p] [720p] [480p] [❌]
   ↓ المستخدم يختار 1080p
المهمة تُنشأ بـ requested_format="1080" ← الطابور/الشريط/الرفع كالمعتاد
```

- **لا فحص مسبق للرابط** (سريع فوري) — الجودات قوالب جاهزة تطابق `fmt_map` في المحرك (best/1080/720/480/audio) — DRY مع `cli.py`
- **حالة معلّقة:** `PENDING: dict[nonce] = {"user_id", "chat_id", "url", "created"}` — في الذاكرة، صلاحية 3 دقائق، تُستبدل عند رابط جديد، وتُنظف كسلاً عند كل استخدام
- **أسماء الـ callback:** نفس مخططهم المعروف `pick:v:<nonce>` / `pick:a:<nonce>` / `pick:q:<nonce>:<quality>` / `pick:x:<nonce>` (إلغاء) — تسهيلًا لأي ذكاء يقرأ الكودين
- **ملكية:** callback يتحقق `from_user.id` و `chat_id` يطابقان الحالة المعلّقة — وإلا رفض
- **انتهاء الصلاحية:** رسالة "⏳ انتهى وقت الاختيار — أرسل الرابط مجددًا"
- **إلغاء:** `pick:x` يحذف الحالة ويرد "تم الإلغاء"
- `/audio` و`/video` يبقيان (للاختصار) لكن **الاختيار يُعرض دائمًا** عند كل رابط (طلبك الصريح)

### الملفات
- تعديل: `app/bot.py` — دالة `_ask_choice(chat_id, user_id, url)` + معالج `on_pick_callback` + تسجيل `CallbackQueryHandler(pattern=r"^pick:")` + تعديل `receive()` (بدل إنشاء المهمة فورًا → عرض الأزرار)
- إضافة: `tests/test_choice.py`

## F5: 🗑️ الحذف الفوري بعد نجاح الإرسال

### التصميم

```
الإرسال ينجح ✅ (send_video/send_audio رجع OK)
   ↓
حذف الملف + مجلد المهمة فورًا + تحديث الصف (file_path=None, file_size=None)
   ↓
التخزين لا يتكدس أبدًا — الملف يعيش ثوانٍ فقط بعد وصوله للمستخدم
```

### القرارات (حالات حدية مهمة)

| الحالة | السلوك |
|---|---|
| إرسال بوت نجح (فيديو أو صوت) | ✅ حذف فوري للملف + المجلد |
| إرسال فشل (سقط لرابط التحميل) | 🕐 **لا حذف** — المستخدم قد يستخدم الرابط (يبقى حتى 24 ساعة) |
| مهمة ويب (`source="web"`) | 🕐 لا حذف — رابط التحميل هو وسيلة التسليم (24 ساعة كالمعتاد) |
| زر MP3 على مقطع محذوف | 🔄 **إعادة تحميل عند الطلب**: المهمة تحفظ `url` — يعيد التحميل (وضع صوت m4a) ثم يحوّل mp3 ويرسل ويحذف — الزر يبقى شغالًا دائمًا |
| صف قاعدة البيانات | يبقى (يحمل url/title لزر MP3) — وcleanup يحذفه بعد انتهاء expires_at |

### التنفيذ

- `app/bot.py` في `watch_and_deliver` بعد نجاح `send_task`:
```python
# الحذف الفوري — نقطة عدم التكدس
from .db import SessionLocal
if j and j.source == "telegram":
    try:
        folder = Path(j.file_path).parent if j.file_path else None
        if j.file_path:
            Path(j.file_path).unlink(missing_ok=True)
        if folder:
            shutil.rmtree(folder, ignore_errors=True)
        with SessionLocal() as db:
            row = db.get(Job, jid)
            if row:
                row.file_path = None
                row.file_size = None
                db.commit()
    except Exception:
        pass
```
- `app/bot.py` في `on_mp3_button`: عند غياب الملف → رسالة "🎧 جارٍ إعادة التحميل للتحويل…" → `UniversalExtractor().download(job.url, tmpdir, preferred="audio")` → تحويل m4a→mp3 → إرسال → حذف الملفين
- `app/worker.py` و`cleanup.py`: بلا تغيير (cleanup شبكة أمان للويب والفشل)

### الملفات
- تعديل: `app/bot.py` (الحذف الفوري + MP3 المعاد التحميل)
- إضافة: `tests/test_choice.py` يتضمن اختبار أن الملف يُحذف بعد النجاح (وحدة معقولة)

## التحقق

1. `uv run --project . python -m pytest tests/ -q` → كل الاختبارات (القديمة + الجديدة) خضراء
2. `python -m compileall app` → صياغة سليمة
3. تجربة بوت حية: إرسال رابط → أزرار تظهر → اختيار 720p → شريط تحميل → رفع % → مقطع + زر MP3
4. `docker compose up --build -d` → الحاويات الست سليمة
5. تجربة رابط يوتيوب + تيك توك بعد التعديل → نفس النجاح السابق (المحرك لم يُلمس)
